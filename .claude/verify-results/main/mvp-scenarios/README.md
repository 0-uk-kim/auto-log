## 찍으면서 확인된 결함

**순서 변경이 끈 거리보다 훨씬 많이 이동한다.** 손잡이를 정확히 한 행(216px)만 내리면 1칸이
아니라 10칸 아래로 떨어진다. Room `clip_order` 저장값으로 확인했다.

```
BEFORE 35,37,39,28,42,71,72,30,31,32,34,76,81
AFTER  37,39,28,42,71,72,30,31,32,34,35,76,81   # 35번이 0 → 10
```

MOVE 이벤트를 3개로 주든 12개로 주든 결과가 같아 입력 밀도와는 무관하다.
`s2-list-reorder.mp4` 에 그대로 찍혀 있다 — 이 영상은 "순서가 유지된다"는 증거이자
"의도한 자리에 놓이지 않는다"는 증거다. 관련 코드는 `list/DragDropState.kt:69` 의 `onDrag`.

## 녹화 시 주의

`screenrecord` 가 예고 없이 10~20초에서 끊겨 뒷부분이 통째로 사라지는 일이 잦다.
결정적인 장면을 영상 끝에 두지 말고, 길게 찍어야 하면 녹화 중 `screencap`·`uiautomator dump`
호출을 피한다. 폴더블이라 `screencap -d` / `screenrecord --display-id` 로 디스플레이를
반드시 명시해야 한다 (커버 화면 `4630947123231501204`).
