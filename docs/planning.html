오토로그 (AutoLog)

Android · 자동 브이로그 생성 앱 · 기획 문서
하루 동안 촬영한 짧은 영상들을 정렬된 순서대로 이어붙여 한 편의 브이로그로 만들어 주는 앱.
촬영 → 목록 정리 → 편집 → 브이로그 생성 → 공유 의 흐름을 하나의 앱에서 끝낸다.

1. 개요

브이로그를 만들려면 보통 촬영 앱과 편집 앱을 오가며 클립을 모으고, 순서를 맞추고, 내보내는 과정을 거쳐야 한다. 오토로그는 이 과정을 촬영한 날짜 단위로 자동 묶어 압축한다. 사용자는 그날 찍은 클립의 순서만 확인하면 브이로그 한 편이 나온다.

2. 사용자 플로우

메인 진입점은 카메라 화면이며, 여기서 나가는 통로는 둘이다. 좌측 하단은 방금 촬영한 영상의 미리보기 재생 화면으로, 우측 하단은 날짜별 영상 목록으로 이어진다. 목록에서 하루치 클립의 순서를 정리한 뒤 브이로그를 생성하고 공유하는 것이 1차 개발의 전체 흐름이다.

1차 개발 범위 — 점선으로 표시한 클립 편집은 2·3차 대상이다. 1차에서 영상 목록의 클립을 누르면 미리보기(재생)까지만 제공하고, 촬영 후 즉시 편집도 제공하지 않는다.

3. 기능 명세

3-1. 동영상 촬영 메인

  • 앱의 기본 진입 화면이자 핵심 기능.
  • 촬영이 끝나도 화면을 벗어나지 않고 카메라 상태를 유지한다 (기본 동작).
  • 1차는 세로(9:16) 촬영으로 고정한다. 가로 촬영 지원은 후속 과제다.
  • 좌측 하단 — 방금 촬영된 영상의 썸네일. 누르면 미리보기 재생 화면으로 이동한다. 직전 촬영본이 있을 때만 노출한다.
  • 우측 하단 — 촬영된 영상 목록 보기. 누르면 날짜별 영상 목록으로 이동한다.

3-2. 촬영 후 즉시 편집 1차 제외

  • 방금 촬영한 영상을 바로 손볼 수 있게 하는 기능. 좌측 하단 → 미리보기 재생 화면에서 편집으로 이어진다.
  • 편집 기능 자체가 2·3차 개발 대상이므로 1차 개발에서 제외한다.
  • 1차에서 좌측 하단은 미리보기 재생까지만 담당한다.

3-3. 영상 목록 (날짜별)

  • 특정 날짜에 촬영된 영상을 한 화면에 모아 보여준다. 예) 9월 14일 촬영분.
  • 드래그 등으로 영상 순서를 변경할 수 있다. 이 순서가 브이로그의 재생 순서가 된다.
  • 각 영상을 탭하면 미리보기로 해당 클립을 재생한다. 순서를 정하기 전에 내용을 확인하는 용도이며, 1차 개발에 포함된다.
  • 미리보기에서 좌우 스와이프로 목록 순서를 따라 이전/다음 클립으로 이동한다.
  • 편집 화면 진입은 미리보기에서 이어지며, 편집 기능이 들어오는 2차부터 열린다.
  • 이어보기 — 편집 결과를 확인할 목적으로 앞/뒤 클립의 3초를 함께 재생한다. 3차
  • 각 영상의 편집 여부를 목록에서 구분할 수 있게 표시한다.

3-4. 조회 날짜 선택

  • 영상 목록 화면에서 달력을 띄워 다른 날짜로 이동한다. 예) 7월 3일 목록으로.
  • 달력에서 영상이 존재하는 날짜를 시각적으로 구분한다.
  • 브이로그 생성 여부도 날짜별로 구분한다.

3-5. 브이로그 생성

  • 영상 목록 화면 우측 FAB으로 실행한다.
  • 목록에 보이는 순서 그대로 영상을 이어붙인다.
  • 생성 결과를 미리보기로 확인할 수 있다.

3-6. 공유

  • 완성된 브이로그를 인스타그램, 네이버 블로그 등 SNS로 공유한다.
  • 갤러리에 저장해 개인 소장할 수 있다.

5. 개발 단계

편집 관련 기능을 뒤로 미루고, 촬영 → 날짜별 묶기 → 이어붙이기 → 공유라는 핵심 흐름을 먼저 완성한다.

단계범위포함 기능
1차 자막과 편집을 제외한 전체 흐름. 찍고, 순서 맞추고, 이어붙여 공유하는 것까지 동작하는 상태.
편집 기능이 없으므로 촬영 후 즉시 편집도 함께 제외한다.		 촬영 · 좌측 하단 미리보기 · 우측 하단 목록 진입 · 날짜별 목록 · 순서 변경 · 클립 미리보기 · 달력 · 브이로그 생성 · 결과물 미리보기 · 공유/저장
2차 클립 단위 자막 추가. 이때 미리보기 재생 화면 → 편집 화면 경로가 처음 열린다. 편집 화면 진입 · 구간 지정 · 자막 렌더링
3차 클립 트리밍 등 본격 편집과 촬영 후 즉시 편집. 구간 자르기 · 앞/뒤 3초 이어보기 · 편집 여부 표시 · 촬영 후 즉시 편집
n차 1차에서 기본값으로 고정한 항목의 사용자 선택권을 여는 후속 과제. 해상도·프레임레이트 옵션 · 가로(16:9) 촬영 지원 · 배경음악 삽입
1차 개발 시 유의 — 3-3의 "이어보기"와 "편집 유무 상태 체크"는 편집 기능에 종속되므로 3차로 미뤄도 되지만, 목록 데이터 모델에는 편집 여부 필드를 처음부터 넣어 두는 편이 나중 마이그레이션 비용을 줄인다.

6-1. 촬영 기본값

1차는 세로 촬영으로 고정한다. 결과물이 인스타그램 등 SNS로 공유되는 것이 전제이므로, 기본값은 이들 플랫폼이 그대로 받아주는 9:16 규격을 따른다. 아래는 이 값을 정할 때 참고한 사례다.

기준규격비고
Instagram Reels 1080 × 1920 (9:16)
30fps 이상		 최소 720p, 권장 1080×1920. 9:16은 릴스 탭에서 잘림이나 검은 띠 없이 표시되는 유일한 비율이다.
TikTok / Shorts 1080 × 1920 (9:16) 릴스와 사실상 동일한 세로 규격을 공유한다. 가로 영상은 레터박스가 붙고 노출에도 불리하다.
코덱 · 비트레이트 H.264 + AAC
5~10Mbps		 주요 플랫폼이 공통으로 요구하는 조합. 파일은 1GB 이하를 권장한다.
저장 용량 1080p/30 ≈ 4K/30의 1/3~1/4 1080p 30fps는 분당 수십~130MB 수준, 4K 30fps는 분당 약 375MB. 하루치 클립을 모두 보관하는 앱에서는 차이가 크다.
CameraX Quality.FHD + FallbackStrategy 기기가 FHD를 지원하지 않으면 CameraX가 가장 가까운 화질로 대체하도록 맡길 수 있다.
1차 기본값 — 1080 × 1920 (9:16 세로 고정) · 30fps · H.264 + AAC. 기기가 지원하지 않으면 CameraX FallbackStrategy로 한 단계 낮은 화질을 쓴다.
근거 — ① 공유 대상 플랫폼이 모두 이 규격을 권장하므로 업로드 시 잘림이나 레터박스가 없다. ② 세로 고정이라 클립 방향이 섞이지 않고, 병합 시 회전 보정이 필요 없다. ③ 클립 길이에 제한을 두지 않기로 한 만큼 4K 대신 1080p를 택해 저장 부담을 1/3~1/4로 낮춘다.
세로 고정에 따른 영향 — 네이버 블로그처럼 가로 영상이 자연스러운 곳에서는 좌우에 여백이 생긴다. 1차 공유 대상을 세로 영상을 그대로 받는 SNS(인스타그램 등) 위주로 보고, 가로(16:9) 촬영 지원은 후속 과제로 둔다.
